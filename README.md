# Timekeeper plugins

The plugin store for [Timekeeper](../Timekeeper). The app's **Plugins** screen lists what is in `index.json` here and installs plugins from this repository, checking every file's SHA-256 and the signature of `index.json`.

Timekeeper reads plugin repositories from GitHub (`https://github.com/Riktastic/timekeeper-plugins` by default), from any HTTPS address serving these files, or from a folder; a user can add several on the Plugins screen. The app downloads `index.json`, `index.json.sig` and the files the index lists, so a repository needs nothing more than this layout. A development build of Timekeeper also adds this folder when it sits next to the Timekeeper source.

To publish your own repository, copy this layout, run `build-index.ps1` with your own signing key, and push it to GitHub.

| Plugin | What it adds | Works on |
|---|---|---|
| `teams-meetings` | Teams calls and meetings, also in the background; the meeting title decides the customer | Windows only |
| `outlook` | Subject and mail domains of the selected or open Outlook item; mail sent and received per customer | Windows only |
| `outlook-calendar` | Your appointments, which the daily review offers as time for the customer of the attendees or subject | Windows only |
| `office-paths` | Full path of the Word, Excel or PowerPoint document and the Explorer folder in front | Windows only |
| `remote-desktop` | Remote Desktop Manager entry, folder and server; Remote Desktop Connection server | Windows only |
| `terminal-ssh` | The server of SSH sessions in Windows Terminal, PuTTY, Konsole, GNOME Terminal and other terminals | Windows and Linux |
| `admin-tools` | The server, database or domain in SQL Server Management Studio, WinSCP, FileZilla, Hyper-V and VMware consoles and management consoles (Active Directory, DNS) | Windows and Linux |
| `remote-workspaces` | The Citrix, Azure Virtual Desktop, Windows 365 or Horizon workplace you work in | Windows and Linux |
| `vscode-git` | The folder and git repository of the VS Code (or Cursor) window in front | Windows and Linux |
| `web-addresses` | The domain of the page in front in Edge and Chrome, matched like a mail domain; the customer's Microsoft tenant, Azure subscription and Power BI or Fabric workspace in Azure portal, Entra, Power BI and Fabric addresses | Windows only |
| `ticket-ids` | Ticket IDs (Jira, TopDesk, ServiceNow) in window titles, offered as the task | Windows and Linux |
| `networks` | Wi-Fi network or VPN, as weak evidence for the customer | Windows and Linux |
| `file-changes` | Files saved in customer folders | Windows and Linux |

On Linux, plugins run in PowerShell 7 (`pwsh`), which has to be installed. Plugins that use Outlook, Office or Windows UI Automation through COM, or the Windows registry, are Windows only: `platforms` in their `plugin.toml` says so, Timekeeper shows "Windows only" in the store, and their documentation starts with a **Works on** line. `Run-Tests.ps1` checks that the two agree.

## Layout

```text
index.json              generated by build-index.ps1
index.json.sig          its Ed25519 signature
plugins/<id>/           one folder per plugin: plugin.toml plus its files
shared/protocol.ps1     protocol helpers, copied into PowerShell plugins
docs/protocol.md        how plugins and Timekeeper talk
test/<id>.tests.ps1     unit tests per plugin
test/Run-Tests.ps1      runs all unit tests
test/Test-Plugin.ps1    runs a plugin without the app and prints what it sends
```

## Changing or adding a plugin

1. Edit or add `plugins/<id>/` and raise `version` in `plugin.toml`. Keep its `README.md` (named by `docs` in `plugin.toml`) up to date: the app shows it in its help screen. Start it with a `# Title`; describe what the plugin does, how to set it up, what it reads, and its settings.
2. Keep the logic in functions and end the setup with `if ($script:testMode) { return }` before `Wait-Initialize`, so tests can load the functions without starting the plugin.
3. Write or update `test/<id>.tests.ps1` (see `test/TestKit.ps1`) and run all tests:
   `powershell -ExecutionPolicy Bypass -File test\Run-Tests.ps1`
4. Try it for real: `powershell -ExecutionPolicy Bypass -File test\Test-Plugin.ps1 -Plugin <id>`.
5. Run `powershell -ExecutionPolicy Bypass -File build-index.ps1`. It signs the index with `%USERPROFILE%\.timekeeper\store-signing.key`.
6. Commit. The store in the app shows an update.

Every plugin needs a test file and documentation: `Run-Tests.ps1` fails when either is missing. Keep plugin files ASCII; Windows PowerShell 5.1 reads files without a byte order mark as ANSI.

See [docs/protocol.md](docs/protocol.md) for the messages and the manifest.
