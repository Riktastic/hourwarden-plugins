# Timekeeper plugins

The plugin store for [Timekeeper](../Timekeeper). The app's **Plugins** screen lists what is in `index.json` here and installs plugins from this repository, checking every file's SHA-256 and the signature of `index.json`.

For now the store is this local folder (setting **Plugin store** in Timekeeper; empty means this folder next to the Timekeeper source). Later this repository moves to GitHub and the app downloads from there; the layout stays the same.

| Plugin | What it adds |
|---|---|
| `teams-meetings` | Teams calls and meetings, also in the background; the meeting title decides the customer |
| `outlook` | Subject and mail domains of the selected or open Outlook item; mail sent and received per customer |
| `outlook-calendar` | Your appointments, which the daily review offers as time for the customer of the attendees or subject |
| `office-paths` | Full path of the Word, Excel or PowerPoint document and the Explorer folder in front |
| `remote-desktop` | Remote Desktop Manager entry, folder and server; Remote Desktop Connection server |
| `terminal-ssh` | The server of SSH sessions in Windows Terminal, PuTTY and other terminals |
| `vscode-git` | The folder and git repository of the VS Code (or Cursor) window in front |
| `web-addresses` | The domain of the page in front in Edge and Chrome, matched like a mail domain |
| `ticket-ids` | Ticket IDs (Jira, TopDesk, ServiceNow) in window titles, offered as the task |
| `networks` | Wi-Fi network or VPN, as weak evidence for the customer |
| `file-changes` | Files saved in customer folders |

## Layout

```text
index.json              generated by build-index.ps1
index.json.sig          its Ed25519 signature
plugins/<id>/           one folder per plugin: plugin.toml plus its files
shared/protocol.ps1     protocol helpers, copied into PowerShell plugins
docs/protocol.md        how plugins and Timekeeper talk
test/<id>.tests.ps1     unit tests per plugin
test/Run-Tests.ps1      runs all unit tests
test/Test-Plugin.ps1    runs a plugin without the app and prints what it sends
```

## Changing or adding a plugin

1. Edit or add `plugins/<id>/` and raise `version` in `plugin.toml`.
2. Keep the logic in functions and end the setup with `if ($script:testMode) { return }` before `Wait-Initialize`, so tests can load the functions without starting the plugin.
3. Write or update `test/<id>.tests.ps1` (see `test/TestKit.ps1`) and run all tests:
   `powershell -ExecutionPolicy Bypass -File test\Run-Tests.ps1`
4. Try it for real: `powershell -ExecutionPolicy Bypass -File test\Test-Plugin.ps1 -Plugin <id>`.
5. Run `powershell -ExecutionPolicy Bypass -File build-index.ps1`. It signs the index with `%USERPROFILE%\.timekeeper\store-signing.key`.
6. Commit. The store in the app shows an update.

Every plugin needs a test file: `Run-Tests.ps1` fails when one is missing. Keep plugin files ASCII; Windows PowerShell 5.1 reads files without a byte order mark as ANSI.

See [docs/protocol.md](docs/protocol.md) for the messages and the manifest.
